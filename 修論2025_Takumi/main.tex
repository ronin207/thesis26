    \begin{coverabstract}
       Zero-knowledge virtual machines (zkVMs) prove an arbitrary program executed correctly under one universal relation, so a predicate update is a program edit, making them an attractive substrate for post-quantum anonymous credentials whose signatures evolve as standards mature. But a zkVM prover works over a $31$-bit field, while low-constraint post-quantum signatures of the Legendre/power-residue-PRF family (Loquat, PLUM) verify over a large prime field, so every operation pays a multi-limb \emph{field-mismatch tax}. This thesis asks whether such a credential can run inside a zkVM on consumer hardware without breaking the security it must provide, and if it cannot run natively, what makes it run. From our findings, an application-defined precompile absorbs the tax, turning a verification that does not complete in over five hours into a $14.24$-minute succinct proof of PLUM verification at the $80$-bit level (Apple M5~Pro, $24$~GB), and a \emph{cost criterion}, built on a trace-area model, decides when such a precompile pays. Calibrated on a suite of three precompiles, the criterion yields a falsified prediction: at matched security, swapping the bespoke Griffin-$\mathbb{F}_p^{192}$ hash for a software SHA-3 is faster ($13.24$ versus $14.24$~min, $n{=}5$), so the custom-precompiled algebraic hash loses even to a standard hash run in software, an inversion whose sign the cost model postdicts. However, we observe that deployable post-quantum anonymity is not reached: the zero-knowledge wrap fits the memory budget yet ships only pairing-based, hence not post-quantum. This dual obstruction, which we locate, holds independently of the five explicitly stated open assumptions on which the thesis's positive results rest.
    \end{coverabstract}
