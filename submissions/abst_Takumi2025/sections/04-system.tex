\section{The Precompile Suite}
A \emph{precompile} is a custom accelerator for a single operation that the program calls directly, so the operation runs at full speed instead of being emulated. PLUM verification has three operations heavy enough to warrant one: a hash, a large-number multiplication, and the pseudorandom check at PLUM's core. We build an accelerator for each in SP1~\cite{succinct2024sp1}, the zkVM this thesis uses, over PLUM's $199$-bit numbers, each with a written soundness argument, using the Griffin hash~\cite{cryptoeprint:2022/403} for the first. The accelerated layer preserves PLUM's unforgeability so long as each accelerator faithfully computes its operation and the zkVM binds it to the program (\S5). The criterion then separates the three. The Griffin accelerator restores feasibility (\S4) yet still proves slower than a plain software SHA-3. The multiplication accelerator is predicted not to pay, because the zkVM already ships a multiplier that serves it. The pseudorandom check, the one operation that cannot be moved to smaller numbers, does pay. It runs $10.33\times$ cheaper by removing the per-step overhead of the slow version.
